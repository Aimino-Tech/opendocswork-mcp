# Product UI Patterns

For productivity/developer tools, organize screens around decisions and current state rather than feature categories. Put status, blockers, next action, and evidence near each other. Prefer a stable shell with context panels/drawers to page-hopping.

Use cards only for independently scannable units. Use tables for comparison across many rows/columns, lists for narrative/heterogeneous items, and split panes when users repeatedly compare detail against a collection. Provide empty/loading/error states as designed states, not afterthoughts.
